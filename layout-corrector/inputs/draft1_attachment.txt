ТЗ на подготовку обучения модели автоматической коррекции раскладки клавиатуры (RU ↔ EN)

## 1. Назначение и режим работы

**Цель:** on-device инструмент, который при наборе текста определяет, что пользователь печатает не в той раскладке, и заменяет символы на корректные. Пример: `ghbdtn` → `привет`.

**Ключевое ограничение:** модель **не генерирует текст**. Она выполняет **классификацию** окна символов, после чего **детерминированный маппер** выполняет замену по фиксированной таблице соответствия клавиш QWERTY ↔ ЙЦУКЕН. Это полностью исключает галлюцинации.

**Классы выхода (9 классов):**
- `en` — корректный английский
- `ru` — корректный русский
- `en_from_ru` — английский, набранный в русской раскладке
- `ru_from_en` — русский, набранный в английской раскладке
- `neutral` — код, URL, цифры, e-mail, смешанный ввод (не трогать)

**Бюджет задержки:** весь пайплайн от события нажатия клавиши до замены текста — **< 50 ms** на CPU.

## 2. Архитектура модели

| Компонент | Спецификация |
|---|---|
| **Тип** | Классификатор (не генеративная LLM) |
| **Основа** | Ensemble: multi-scale CNN + character-level Transformer |
| **Слоёв Transformer** | 4 |
| **Hidden size** | 128–256 |
| **Attention heads** | 4–8 |
| **Окно контекста** | 20 символов (фиксированное) |
| **Параметров** | 1–5M |
| **Размер в CoreML (INT4)** | ~14 MB |
| **Токенизация** | character-level |
| **Выход** | softmax по 9 классам |
| **Пулинг** | оба потока (CNN + Transformer) пулятся в единый linear head |

**Почему не LSTM:** LSTM-архитектура (как в KeyboardSwitcher) даёт >99% accuracy, но хуже обобщает на代码 и смешанные языки. Transformer + CNN ensemble — оптимальный баланс.

## 3. Датасет

### 3.1. Источники

| Источник | Что даёт |
|---|---|
| Wikipedia RU dump | 835K предложений русского текста |
| Wikipedia EN dump | 835K предложений латиницы |
| Субтитры RU/EN | Разговорный стиль, короткие фразы |
| `anzorq/kbd_lat-835k_ru-3M` (HuggingFace) | Готовый датасет: 835K латинских + 3M русских предложений |

### 3.2. Генерация пар

1. Берётся чистый русский текст → программно «набирается» в английской раскладке → метка `ru_from_en`.
2. Берётся чистый английский текст → программно «набирается» в русской раскладке → метка `en_from_ru`.
3. Чистый русский → метка `ru`. Чистый английский → метка `en`.
4. Код/URL/цифры/e-mail → метка `neutral`.

### 3.3. Аугментация

- **Опечатки:** пропуск символа, дублирование символа, перестановка соседних символов.
- **Регистр:** случайная смена регистра символов.
- **Mixup:** смешивание эмбеддингов двух примеров с линейной интерполяцией меток.
- **Label smoothing:** 0.1.
- **Смешанные параграфы:** чередование RU/EN предложений внутри одного окна.

### 3.4. Объём

- **Train:** 5–10M примеров.
- **Validation:** 500K.
- **Test:** 500K (несбалансированный: с акцентом на код, URL, имена, `kubectl`, `github.com`, `user@example.com`).

## 4. Гиперпараметры обучения

| Параметр | Значение |
|---|---|
| **Loss** | CrossEntropyLoss |
| **Optimizer** | AdamW |
| **Learning rate** | 2e-4 |
| **Weight decay** | 0.01 |
| **Batch size** | 128 |
| **Epochs** | 20 (early stopping по val accuracy, patience=3) |
| **Scheduler** | CosineAnnealingLR |
| **Label smoothing** | 0.1 |
| **Dropout** | 0.1 |
| **Gradient clipping** | 1.0 |
| **Warmup** | 500 шагов |
| **Seed** | 42 (фиксировать для воспроизводимости) |

## 5. Метрики приёмки

| Метрика | Порог | Условие |
|---|---|---|
| **Overall accuracy** | ≥ 99.0% | на тестовой выборке |
| **Accuracy по классу `neutral`** | ≥ 99.5% | код/URL/цифры не трогать |
| **False positive rate (общий)** | < 0.1% | ошибочное «исправление» корректного текста |
| **False positive rate на коде/URL** | < 0.01% | `kubectl`, `github.com` и т.п. |
| **Latency (CPU, полный цикл)** | < 50 ms | event tap → замена |
| **Latency (Neural Engine)** | < 5 ms | INT4 CoreML |

**Метрики, которые НЕ используются:** BLEU, perplexity, ROUGE — это генеративные метрики, для классификации раскладки бессмысленны.

## 6. Квантование и деплой

| Этап | Действие |
|---|---|
| **Профилирование** | Layer-by-layer sensitivity analysis через `get_weights_metadata` |
| **Стратегия** | Mixed INT4/INT8: ранние сверточные слои → INT4, attention и финальный classification head → FP16 или INT8 |
| **INT4 palettization** | Селективно, ~50–60% снижение latency на Neural Engine |
| **Формат** | CoreML (iOS/macOS), ONNX INT8 (Windows/Linux) |
| **Размер после сжатия** | 14–20 MB |
| **Порог уверенности** | 0.9. Если softmax < 0.9 — не исправлять |

## 7. Дополнительные требования

### 7.1. Адаптивная кривая уверенности
Короткий ввод (3–5 символов) требует **более высокого порога уверенности**, чем длинный (15–20 символов). Реализация: отдельные пороги для каждой длины окна.

### 7.2. Механизм отмены (Esc to undo)
После автоматической замены пользователь может нажать Esc в течение 10 секунд для отката. Буферизуется до 100 символов после замены.

### 7.3. Learned exceptions
Если пользователь отклонил замену для слова — это слово запоминается как исключение (case-folded). Повторно не исправляется.

### 7.4. Инвалидация отмены
Отмена сбрасывается при: клик, смена фокуса, Enter, стрелки, ручное переключение раскладки.

### 7.5. Обработка кода и URL
Модель обучается на примерах, где `kubectl`, `github.com`, `npm install`, `user@example.com`, `https://` **не должны** классифицироваться как `ru_from_en`.

### 7.6. Смешанные языки
Окно может содержать русский и английский одновременно. Модель должна корректно классифицировать **только последнее слово**, не затрагивая предыдущий контекст.

### 7.7. Пер-языковые пары
Для пар `en→ru` и `ru→en` — отдельные пороги `EarlyDetectionMinChars`, `ConfidenceAtMinChars`, `ConfidenceAtMaxChars`, `ConsecutiveAgreementCount`.

## 8. Что категорически запрещено

- Использовать генеративную LLM (GPT, Llama, Qwen и т.п.) в любой форме.
- Позволять модели «додумывать» или продолжать текст.
- Использовать словарный подход как единственный метод — он ломается на именах, коде, URL, аббревиатурах.
- Применять INT4 ко всем слоям без профилирования — attention-слои теряют точность сильнее.
- Оценивать качество через BLEU/perplexity.

## 9. Артефакты на выходе

1. Обученный чекпоинт (PyTorch).
2. CoreML `.mlpackage` (INT4 mixed).
3. ONNX INT8 для Windows/Linux.
4. Таблица маппинга QWERTY ↔ ЙЦУКЕН (детерминированный модуль).
5. Отчёт с метриками на тестовой выборке (accuracy, FP rate по классам, latency).
6. Скрипт воспроизведения обучения (seed, версии библиотек).
