# L4. Platform API audit (primary sources), revision 2

Run dates: first pass 2026-10-30, second pass 2026-11-01 (answer to the third external review, items "L4 corrections").
Every card names one API, one source with its class, a quote of at most about 40 words, a verdict, the place of the specification
that depends on it, and the test that checks it. A claim whose page could not be read, or whose page does not say it, is
**UNVERIFIED** and becomes a spike item, never a statement of fact in the specification.

**Source classes** (they are not interchangeable):

| Class | Meaning |
|---|---|
| `MS` | Microsoft Learn page (the vendor's reference). |
| `AD` | Apple Developer documentation page, or an Apple archived technical note. |
| `AH` | Apple SDK header text, read in a third-party copy of a named SDK version. It shows the declaration of that SDK, not the behaviour of every macOS version. |
| `DTS` | Answer by Apple Developer Technical Support staff on the developer forum. |
| `AF` | Post by a third party on the Apple developer forum or a mailing list (not Apple staff). Evidence of a report, not of a documented behaviour. |
| `RV` | The external reviewer's report. The page was not read; the row is UNVERIFIED. |

Verdicts: `CONFIRMED` (the page says it), `NUANCE` (the page says something narrower or different), `UNVERIFIED` (page silent or not read).
The column "Read" says whether the quote was read again in the second pass; the fetch tool refused two pages in that pass
(`SetValue`, the Russian layout page), their rows keep the first-pass reading and say so.

## Result

* Windows: 35 cards; verdicts {'CONFIRMED': 25, 'NUANCE': 6, 'UNVERIFIED': 4}. The design-changing findings are unchanged: W2 (the KLID of the foreground thread cannot be read, so the layout is identified by fingerprint), W3 (the fingerprint needs flag 4, Windows 10 1607 or newer) and W4 (a silently removed hook cannot be detected without a second observer), and now W5e (one raw-input registrant per process, so the canary window is the only one).
* macOS: 23 cards; verdicts {'CONFIRMED': 10, 'NUANCE': 3, 'UNVERIFIED': 10}. Confirmed by Apple pages: `CGEventTapOptions`, `CGEventTapLocation`, `tapEnable`, the AppKit secure-text-field subrole, `SMAppService`, TN2150, and the two DTS statements; the macOS design rests on spikes S-6 and S-7 for everything else.
* Statements of the specification that rest on a row with the verdict UNVERIFIED are hypotheses until their spike has a filed result (13.7); none of them is a requirement of the first release by itself.
* Nothing in this audit is taken from memory; where a page could not be read the row says so.
