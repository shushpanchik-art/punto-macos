# L4. Platform API audit (primary sources)

Run date: 2026-10-30. Method: every claim of section 13.7 about a platform API was checked against the vendor page in the main
session (`WebFetch`), and each verdict carries a quote of at most 40 words. A claim whose page could not be read, or whose page does
not say it, is **UNVERIFIED** and becomes a spike item, never a statement of fact in the specification.

The first attempt (two sub-agents) produced no evidence: their permission prompts for `WebFetch` timed out and they correctly
did not work around the block. Their drafts were discarded; this file replaces them.

Verdicts: `CONFIRMED` (page says it), `NUANCE` (page says something narrower or different), `UNVERIFIED` (page silent or unreadable).

## Windows (Microsoft Learn)

| Id | Claim | Verdict | Quote | What the specification says (v3.1) |
|----|-------|---------|-------|------------------------------------|
| W1a | HKL structure | CONFIRMED | "The low word contains a Language Identifier for the input language and the high word contains a device handle to the physical layout of the keyboard." (GetKeyboardLayout) | The HKL is an opaque value; the low word is never used to decide which key table applies. |
| W1b | `GetKeyboardLayout(idThread)` works for another process's thread | UNVERIFIED | The page only says "The identifier of the thread to query, or 0 for the current thread." | Use is allowed but the first spike (13.7 spike S-2) must show it returns the foreground application's layout on Windows 10 and 11 for elevated and normal targets. |
| W2 | `GetKeyboardLayoutName` for another thread | NUANCE | "Retrieves the name of the active input locale identifier (formerly called the keyboard layout) for the calling thread." | The KLID of the foreground thread **cannot** be read by a documented call. KLID is therefore not the decision input. |
| W2b | Meaning of the name | NUANCE | "The input locale identifier is a broader concept than a keyboard layout, since it can also encompass a speech-to-text converter, an Input Method Editor (IME), or any other form of input." | A layout is identified by its **fingerprint** (94 key states translated with that HKL), compared with the supported table; KLID is diagnostic only. |
| W3a | `ToUnicodeEx` flag 4 | CONFIRMED | "If bit 2 is set, keyboard state is not changed (Windows 10, version 1607 and newer)" | The fingerprint needs Windows 10 1607 or newer; older versions: layout support OFF for auto-correction. |
| W3b | `ToUnicodeEx` side effect without the flag | CONFIRMED | "As ToUnicodeEx translates the virtual-key code, it also changes the state of the kernel-mode keyboard buffer." | The call without flag 4 is forbidden. Whether flag 4 also protects dead-key state is not stated → regression test RT-15 (type a dead-key sequence after a fingerprint). |
| W3c | explicit `dwhkl` | CONFIRMED | "The input locale identifier used to translate the specified code. This parameter can be any input locale identifier previously returned by the LoadKeyboardLayout function." | A foreground-thread HKL from `GetKeyboardLayout` is not documented as accepted: spike S-2 checks that `ToUnicodeEx` with it returns the expected characters; if not, the layout is OFF. |
| W4a | LL hook timeout | CONFIRMED | "If the hook procedure times out, the system passes the message to the next hook. However, on Windows 7 and later, the hook is silently removed without being called. There is no way for the application to know whether the hook is removed." | Hook health needs an independent canary (hook-loss detector, 13.5 row 13). |
| W4b | timeout value | CONFIRMED | "The maximum timeout value the system allows is 1000 milliseconds (1 second)." The value is `LowLevelHooksTimeout` under `HKEY_CURRENT_USER\Control Panel\Desktop`. | The hook callback does only a bounded copy to a queue (budget in 7.5, phase P1); never allocates, never calls the scorer. |
| W4c | message loop | CONFIRMED | "the thread that installed the hook must have a message loop." | The hook thread has its own message loop and does nothing else. |
| W4d | injected flags | CONFIRMED | `LLKHF_INJECTED`: "Test the event-injected (from any process) flag." `LLKHF_LOWER_IL_INJECTED`: "...from a process running at lower integrity level..." | Both flags mean "ignore as input"; tagging of our own events uses `dwExtraInfo` (page: "Additional information associated with the message."). |
| W5a | Raw Input background | CONFIRMED | RIDEV_INPUTSINK: "If set, this enables the caller to receive the input even when the caller is not in the foreground. Note that hwndTarget must be specified." | Canary uses a message-only window with RIDEV_INPUTSINK. |
| W5b | `WM_INPUT` code | CONFIRMED | "RIM_INPUTSINK (1): Input occurred while the application was not in the foreground." | The canary reads this code. |
| W5c | UIPI and Raw Input | UNVERIFIED | The pages for RegisterRawInputDevices, RAWINPUTDEVICE and WM_INPUT do not mention elevated windows. | Spike S-3 measures it. Until then the canary is a diagnostic, not a guarantee. |
| W5d | `WM_INPUT` cleanup | CONFIRMED | RIM_INPUT: "The application must call DefWindowProc so the system can perform cleanup." (WM_INPUT) | The canary window procedure calls `DefWindowProc` for every `WM_INPUT`. |
| W5e | one registration per device class and process | UNVERIFIED | "About Raw Input" says only: "An application receives raw input from any HID whose top level collection (TLC) matches a TLC from the registration." The external reviewer's statement "one window per process per device class" is **not on the page**. | The canary is the only `RegisterRawInputDevices` caller for the keyboard collection in the process; spike S-3 checks a conflict with other components. |
| W6e | physical keys already down | CONFIRMED | "This function does not reset the keyboard's current state. Any keys that are already pressed when the function is called might interfere with the events that this function generates. To avoid this problem, check the keyboard's state with the GetAsyncKeyState function and correct as necessary." | M2 (manual only) aborts with `modifier_down` when Shift, Ctrl, Alt or a Windows key is physically down; the check uses `GetAsyncKeyState`. |
| W6a | SendInput UIPI | CONFIRMED | "This function is subject to UIPI. Applications are permitted to inject input only into applications that are at an equal or lesser integrity level." and "neither GetLastError nor the return value will indicate the failure was caused by UIPI blocking." | A successful return does not prove delivery: verification by read-back (not by return value). |
| W6b | atomic batch | CONFIRMED | "These events are not interspersed with other keyboard or mouse input events inserted either by the user (with the keyboard or mouse) or by calls to keybd_event, mouse_event, or other calls to SendInput." | One `SendInput` call per replacement chunk. Interleaving between chunks is possible → the 20-event chunk rule and typed-ahead handling stay. |
| W6c | return value | CONFIRMED | "The function returns the number of events that it successfully inserted into the keyboard or mouse input stream." | A short count is a partial write → failure-table row (13.5). |
| W6d | KEYEVENTF_UNICODE | CONFIRMED | "If specified, the system synthesizes a VK_PACKET keystroke. The wVk parameter must be zero." and "wScan specifies a Unicode character which is to be sent to the foreground application." | Surrogate pairs are not mentioned on the page: characters outside the BMP are sent as two events, verified by spike; the target alphabet is BMP only. |
| W7a | TextPattern read-only | NUANCE | The page does not say it. It says: "IValueProvider complements ITextProvider by providing a programmatic way to change the text." | No text of the specification says "TextPattern cannot edit". It says: "TextPattern is used for reading; changing text is a separate pattern." |
| W7b | `SetValue` | NUANCE | "Sets the value of the element." Precondition: "CurrentIsEnabled property must be TRUE, and ... CurrentIsReadOnly property must be FALSE." Whole-value replacement is **not stated**. | `SetValue` is never assumed to replace a range; as M1 it is allowed only for an application whose test replaces the whole field text and passes read-back. |
| W7c | `IsPassword` | NUANCE | "Indicates whether the element contains a disguised password." The page does not say what TRUE means for the text. | Stage 0 treats TRUE as DENY; absence of the flag is not an ALLOW signal. |
| W8 | `EM_REPLACESEL` | CONFIRMED | "Replaces the selected text in an edit control or a rich edit control with the specified text." wParam: "Specifies whether the replacement operation can be undone." Cross-process use is not on the page. | Allowed for classic edit controls; cross-process behaviour is a spike (S-4). |
| W9 | `RegisterHotKey` | CONFIRMED / UNVERIFIED | "Typically, RegisterHotKey also fails if the keystrokes specified for the hot key have already been registered for another hot key." Error code and "foreground application does not receive the key" are **not** on the page. | Registration failure shows a message and leaves the hotkey off; swallowing of the key is verified by spike S-5. |
| W10 | TSF | UNVERIFIED | "TSF provides a simple and scalable framework for the delivery of advanced text input and natural language technologies." Editing another application's text store by a non-text-service application is not on the page. | TSF stays a future experiment (17), not a requirement. |
| W11 | KLIDs | CONFIRMED | Table: US `00000409`, United States-International `00020409`, Russian `00000419`, Russian - Mnemonic `00020419`, Russian (Typewriter) `00010419`. The page names the column "Keyboard identifier" and does not define "KLID". | KLID values are listed for diagnostics and for the supported-layout list. |
| W12 | key positions of the Russian layout | UNVERIFIED | The text of the page has no per-key table. Layout id on the page: "KLID: 00000419". | The Windows table is generated from `ToUnicodeEx` on a real machine (spike S-2), and the fingerprint is that same function. |
| W13 | layout-change notification | NUANCE | "Sent to the topmost affected window after an application's input language has been changed." lParam: "The HKL input locale identifier." | The message goes to the application that changed. There is **no documented global notification**, so the tool reads the foreground thread's HKL on every key event and caches the fingerprint by HKL value. |
| W14 | Caps Lock | CONFIRMED / NUANCE | "If the low-order bit is 1, the key is toggled." and "The key status returned from this function changes as a thread reads key messages from its message queue. The status does not reflect the interrupt-level state associated with the hardware." | The tool keeps its own Caps Lock state: it is read once through `GetKeyState` at start, at every focus change and after resume, and flipped on every Caps Lock key-down seen by the hook; a mismatch with `GetKeyState` at a word boundary drops the word. |

## macOS (Apple headers and developer forum)

Apple's documentation website could not be read by the fetch tool (client errors for the JSON and HTML endpoints). The primary source
used is the CoreGraphics header text in the public SDK mirror `phracker/MacOSX-SDKs`, `MacOSX11.3.sdk` (the text can lag current
behaviour), plus statements of Apple DTS staff on the developer forum (marked as such). The framework headers `UnicodeUtilities.h`
and `TextInputSources.h` returned binary content and could not be read.

| Id | Claim | Verdict | Quote | What the specification says (v3.1) |
|----|-------|---------|-------|------------------------------------|
| M1 | passive vs active tap | CONFIRMED (header) | "Taps may be passive event listeners, or active filters." | The tool uses a listen-only tap; the `kCGEventTapOptionListenOnly` constant is described as "Constants that specify whether a new event tap is an active filter or a passive listener." |
| M1b | permission APIs | CONFIRMED (DTS) | Apple DTS: "If you're using just using CGEventTap, there's CGPreflightListenEventAccess, CGRequestListenEventAccess, CGPreflightPostEventAccess, and CGRequestPostEventAccess." and "You only need the Accessibility privilege if you're doing other stuff with Accessibility APIs." | Three permissions are tracked separately: ListenEvent (observing), PostEvent (synthetic input, M2), Accessibility (AX range replacement, M1). The mapping of a listen-only tap to ListenEvent is not stated verbatim and is verified on a clean macOS account (spike S-6). |
| M2 | tap disabled events | CONFIRMED (header) | "Out of band event types. These are delivered to the event tap callback to notify it of unusual conditions that disable the event tap." and "An event tap may be re-enabled by calling this function." | On `tapDisabledByTimeout` and `tapDisabledByUserInput` the buffer, the run state and the gate are cleared, the tap is re-enabled at most 3 times in 60 s, then correction is OFF and the user is notified. |
| M2b | does a listen-only tap time out | UNVERIFIED | A forum poster (not Apple staff) reports "I do get tapDisabledByTimeout events periodically." | The handler exists regardless of tap type. |
| M2c | revocation detection | NUANCE (forum, developer) | `AXIsProcessTrusted()` can continue to return true after the entry is removed. A developer's workaround is to try to create a new tap and check for NULL; DTS: "I think the best option there is to accept the quit and relaunch." | A heartbeat every 5 s checks `CGEventTapIsEnabled` and `CGPreflightListenEventAccess`; any failure is a hook-loss event. |
| M9 | tag on synthetic events | CONFIRMED (header) | `kCGEventSourceUserData`: "Key to access a field that contains the event source user-supplied data, up to 64 bits." | The tag is a 64-bit constant of the tool's synthetic events. Whether the callback sees it for events of the same process: spike S-7. |
| M9b | `CGEventKeyboardSetUnicodeString` length | UNVERIFIED | The header comment has no maximum length. | The 20-UTF-16-unit chunk is an engineering limit verified by spike S-7, not a documented fact. |
| M12 | keycode is position based | UNVERIFIED | "Key to access an integer field that contains the virtual keycode of the key-down or key-up event." Layout independence is not stated. | Spike S-6 measures key codes on the Russian - PC layout against the key table. |
| M3 | secure event input | CONFIRMED (Apple TN2150) | "The fix for this problem is to stop passing keyboard events to any intercept process whenever any process has enabled secure event input, whether that process is in the foreground or background." The page names `IsSecureEventInputEnabled` for checking and does not say how to find the process that enabled it. | The signal is global and cannot be attributed to an application: while it is on the gate is DENY and the tap sees no keys; `AXSecureTextField` is only a local hint about one element. Neither makes a field ALLOW. |
| M7 | `UCKeyTranslate` status | UNVERIFIED (reported by the external reviewer) | The reviewer reports that Apple's page marks the function as not recommended and points to `NSEvent.characters(byApplyingModifiers:)`; the page could not be read here. | The macOS fingerprint mechanism is chosen by spike S-6: `UCKeyTranslate` and `NSEvent.characters(byApplyingModifiers:)` must give the same 94 entries on every supported macOS version, with dead keys reported as `\x00`. |
| M6 | input source versus layout | UNVERIFIED | `TISCopyCurrentKeyboardInputSource` returns the selected input source, which can be an input method; `TISCopyCurrentKeyboardLayoutInputSource` returns the layout underneath (reviewer, page not read here). | An input source that is not a plain keyboard layout (IME, handwriting, emoji) makes the pair OFF. The fingerprint decides which layout it is. |
| M4, M5, M8, M10, M11 | `AXSecureTextField` role or subrole, AX range attributes, input-source ids, `RegisterEventHotKey`, `SMAppService` | UNVERIFIED | No readable primary source in this run. The reviewer reports that Apple documents `kAXSecureTextFieldSubrole` as a subrole, and `SMAppService` for macOS 13 and later. | Each is a spike item (section 16.2). The specification names the subrole only as a hint, requires `SMAppService` only on macOS 13+ (the supported minimum), and requires for `RegisterEventHotKey` a declaration from the named SDK plus a registration, conflict and release test (spike S-5). |

## Result

* Windows: 25 rows; the three findings that changed the design are W2 (KLID of the foreground thread cannot be read, so the
  layout is identified by fingerprint), W3 (the fingerprint needs flag 4, Windows 10 1607 or newer) and W4 (a silently removed hook
  cannot be detected without a second observer).
* macOS: 5 rows confirmed from headers, DTS statements or Apple TN2150; the remaining items are spikes.
* Nothing in this audit is taken from memory.
